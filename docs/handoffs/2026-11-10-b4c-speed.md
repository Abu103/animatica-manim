## The bug that had to be fixed first

The suite could not simply be parallelised: the timeline geometry tests failed
at random under `-n 4`.

Manim caches every rendered text as an SVG under `<media_dir>/texts`, keyed by
the text and the style -- **but not by the process**. Two workers that render
the same string at the same time write the same file, and one of them can read
it half written: the text comes out with the wrong size and the geometry
assertions fail.

Reproduction (8 processes, one shared media directory, one string):

```
xml.etree.ElementTree.ParseError: no element found: line 1, column 0
```

Fix: `tests/conftest.py` gives every process its own `media_dir`.

## NOT verified -- the next person has to do this

1. **Push the branch and watch the Linux job.** The CI change (the 45 MB TinyTeX bundle
   instead of the 10m47s apt step) has never run. What to watch:
   - the `LaTeX (TinyTeX bundle)` step must print `LaTeX: TinyTeX bundle ready`.
     If it prints the apt warning instead, the bundle did not work and the job fell
     back -- correct, but slow, and the reason is in the step log.
   - the bundle carries no `varwidth.sty`, which `standalone.cls` requires, so the step
     runs `tlmgr install varwidth` first. `tlmgr` is a symlink to `tlmgr.pl` and needs
     perl, which the ubuntu runner has.
2. **The Windows job now runs the render gate.** It did not before: the suite used to
   render the corpus there. Expect ~60 s more on that job.
3. **The suite now runs on four workers in CI.** `pytest-xdist` is in the `dev` extra.
   If a job ever reports "node down", the worker count is the suspect.

## Two findings that were not fixed

- Neither TinyTeX bundle (`animatica-tex.tar.xz` for Linux, `tinytex-manim.zip` for
  Windows) carries `varwidth.sty`, and `doctor.py`'s `NEEDED_TEX_FILES` does not list
  it. So `animatica doctor` reports LaTeX as OK while the equations silently degrade to
  plain text. The bundles are built by `.github/workflows/build-tinytex.yml` and
  `build-tinytex-windows.yml`; adding `varwidth` to their package lists (and to
  `NEEDED_TEX_FILES`) fixes it.
- The render gate as a CI matrix (one job per component) was **not** done: every matrix
  job repeats the checkout and the dependency install, and that setup costs more than
  the 68 s the gate takes. The matrix would spend 18x the compute for no wall-clock win.
